## Findings

### F-1 — Plan §3 sagt „update" für `commands.go`, der Diff berührt die Datei nicht; die Zwei-Mechanik-Sorge des Plans bleibt im Wrapper-Code offen

- **Kategorie:** LOW
- **Quelle:** Maintainability (Plan-vs-Code-Konformität, kein Hard-Rule- oder ADR-Verstoß)
- **Pfad:** [slice-097 §3](../plan/planning/in-progress/slice-097-rollen-typen-gehen-mit.md),
  Zeile `internal/emit/commands.go — update` · `internal/emit/agents.go:29-101` gegen
  `internal/emit/commands.go:23-77`
- **Befund:** Die Plan-Tabelle deklariert `commands.go` als geändert („update"), mit der
  Begründung „DoD (2): die Klasse folgt den Commands; eine zweite Mechanik für dieselbe Klasse
  driftete". Der Diff lässt die Datei unberührt (`git diff HEAD --stat -- internal/emit/commands.go`
  → leer). Auf der Ebene des **Terminal-Writers** trägt die implementierte Lösung die
  Plan-Absicht wörtlich: `Agents()` ruft exakt denselben `writeSkipIfPresent` (`enforce.go:360`)
  wie `Commands()` — keine zweite Schreib-Mechanik. Auf der Ebene der **Wrapper-Struktur** bleibt
  die vom Plan benannte Sorge aber nur teilweise aufgelöst: `agentFiles()`/`Agents()`/
  `AgentPaths()`/`AgentFile()` sind eine fast wortgleiche zweite Ausfertigung von
  `commandFiles()`/`Commands()`/`CommandPaths()`/`CommandFile()` (Loop über eine Liste,
  Pfad-Accessor, Einzeldatei-Getter) — keine der vier Funktionen greift auf eine gemeinsame
  Hilfsfunktion zurück. Ändert ein künftiger Slice z. B. die Fehlerbehandlung oder den
  Datei-Modus in `Commands()`s Schleife, erzwingt nichts eine identische Änderung in `Agents()`s
  Schleife — genau die Drift, vor der die Plan-Begründung warnt, nur auf einer Ebene höher als
  dem einzelnen Schreib-Aufruf. Weder der Plan (§7 Closure-Notiz ist noch leer) noch ein
  Code-Kommentar hält diese Präzisierung fest.
- **Verifizierbar:** ja (strukturell) — ein Diff, der `Commands()`s Loop-Verhalten ändert, ohne
  `Agents()` gleichzeitig anzufassen, zeigt die Drift; kein Test bricht dabei.

- **Kategorie:** LOW
- **Quelle:** Maintainability (Doku-Drift/latente Wartungsfalle) — kein MR-017-Verstoß, im

- **Pfad:** [slice-097 DoD (1)(e)](../plan/planning/in-progress/slice-097-rollen-typen-gehen-mit.md)

- **Befund:** Plan und Test wiederholen wörtlich dieselbe Begründung: „die Verzeichnisse
  existieren im Ziel, ihre Dateien nicht" bzw. „die Verzeichnisse existieren im Ziel, diese Datei
  darin nicht". Das ist gemessen falsch: `internal/emit/templates.go:35` hält fest, dass der
  Planning-Index (`docs/plan/planning/README.template.md`) bewusst **nicht** von der

- **Kategorie:** MEDIUM
- **Quelle:** Maintainability / Konsistenz mit etabliertem Muster (kein §3.6-Verstoß — ein
  `test/mutations/`-Fall mit `# verify: full-smoke` existiert, die Klasse ist nicht „unbewacht"
  im Sinn der Regel, nur auf einer langsameren Stufe)
- **Pfad:** `internal/emit/agents.go` (kein `TestAgents_SkipIfPresent`) gegenüber
  `internal/emit/commands_test.go:82` (`TestCommands_SkipIfPresent`),
  `internal/emit/readme_test.go:104` (`TestRootReadme_SkipIfPresent`),
  `internal/emit/templates_test.go:421` (`TestTemplates_SkipIfPresent`)
- **Befund:** Alle drei bestehenden `skip-if-present`-Emitter im Paket `internal/emit` tragen
  einen dedizierten, schnellen Go-Unit-Test, der genau die Eigenschaft „eine bereits vorhandene,
  adopter-angepasste Zieldatei bleibt bei einem zweiten Lauf unverändert" prüft — Teil von
  `make test-go`, damit von `make gates` (`grep -n "^gates:" Makefile` → hängt an `test`, das an
  `test-go` hängt). Für `Agents()` fehlt dieses Gegenstück; DoD (2) verweist stattdessen

  full-smoke` ist laut `AGENTS.md` §4-Tabelle ausdrücklich **Nicht-Gate-Verify** — eine Regression
