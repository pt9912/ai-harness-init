### M-1 — Der Schluss der relativen-Import-Lücke hängt an einem Config-Teil, den Festlegung 3 ausdrücklich nicht bindet

- `kategorie`: MEDIUM (Stilles-Grün-Pfad im Arch-Gate, Eskalation „Gate-Pfad"; Wiederholung von ADR-0094 L-2)
- `quelle`: `LH-QA-01`; AGENTS.md §3.6
- `pfad`: `docs/plan/adr/0095-python-skelett-toolchain-und-schicht-aufloesung.md:80-85`, `:108-111`, `:179`, `:308-309`
- `befund`: Festlegung 5(a) nennt den relativen Import als a-check-Lücke (`0 Befund(e)`, EXIT 0) und
  sagt, das Skelett schließe sie „über ruff `TID252`". Festlegung 3 sagt dagegen, **gebunden** sei allein
  `F` und mypy-strict im `lint`-Rezept; der übrige Regel-Satz sei Gerüst-Inhalt. `TID` samt
  `ban-relative-imports = "all"` gehört nach diesem Wortlaut nicht zur Bindung. Eine Config ohne `TID`
  bricht keine Zeile der Fitness Function — Zeile 4 ist Zusage, am Ziel nicht gesehen —, und
  `domain` könnte per `from ...adapters.driven.store import Store` grün durch a-check und lint laufen.
  Die Begründung des „Gebunden allein"-Satzes (die Zeile bräche sonst nicht, sie bliebe ungeprüft) gilt
  für `F`, nicht für diese Zusage.
- Gegenprobe (Scratchpad `.harness/state/`, a-check `v0.23.2`, Fixture nach Messung 4): relativer Import
  → EXIT=0, `0 Befund(e)`, Hinweis „relativer Import — von diesem Backend nicht extrahiert" (Fall 6
  reproduziert); `from . import main` mit `select` inkl. `TID` und `ban-relative-imports` → lint
  `TID252` (dazu `F401`), `docker build` Exit 1 (Messung 3 reproduziert).
- `verifizierbar`: nein (kein Sensor hält `TID` im emittierten `pyproject.toml`)
- `klasse`: Bedingung ohne benannten Wächter
